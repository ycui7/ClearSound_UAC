## Architecture as built

One XMOS block engine (`lib_audio_dsp` `fd_block_fir`, AN02027), **two independent clients**:

| | DSP effects | sample-rate conversion |
|---|---|---|
| enable | `DIAG:DSP:PRESet` (+ DSD/DoP stream bypass) — nothing else | trim / `DIAG:UPSAMPLing:STATe` |
| valid rates | **all**, including 384 kHz at ratio 1 | only where a family wire rate exceeds host rate |
| at 384 kHz | runs, verified bit-exact | absent, and that is not an error |

Per-slot pop is O(1); all block compute sits at the host-pair boundary. LRCLK is generated
in software by the audiohub loop, so no block compute may ever enter the per-slot path.

## `DIAG:UPSAMPLing:INFO?` field map (read from the format string in `src/extensions/csd_diag_scpi.c:ups_info_q`, verified live: reply is 55 fields)

Base 18 fields (`csd_ups_block.c` witnesses; append-only rule holds indices):

| idx | name | meaning |
|---|---|---|
| 0 | armed | `csd_ups_armed()` — want&&!bypass&&out_hz (regardless of codec grant) |
| 1 | enabled | `csd_ups_is_enabled()` — the client is actually running |
| 2 | want | `csd_ups_get_want()` — operator request (journal-persisted) |
| 3 | in_hz | host rate of the current stream |
| 4 | out_hz | wire rate this stream must emit (0 = none) |
| 5 | usb_ratio | `xua_csd_get_usb_ratio()` — wire/host ratio at the ports |
| 6 | frames | host pairs ACCEPTED by the resampler (incremented once per FRAME_ADVANCE-pair block; == blocks in a healthy stream) |
| 7 | popsL | wire words popped per channel, L (`csd_ups_slot` deliveries) |
| 8 | popsR | same, R |
| 9 | repeatsL | L starvation repeats (ring empty, last word honestly held) |
| 10 | repeatsR | same, R |
| 11 | occ_highL | high-water occupancy of the L wire ring |
| 12 | occ_highR | same, R |
| 13 | rate_rejects | non-family re-configs refused |
| 14 | blocks | polyphase block computes run (== frames when every host pair is accepted) |
| 15 | block_ticks_max | worst single compute burst, 10 ns ticks |
| 16 | rate_calls | rate hand-overs seen |
| 17 | last_req_hz | last rate asked for |

Tail 37 fields (mic decimator + raw ADC/xfer witnesses):

| idx | name | meaning |
|---|---|---|
| 18 | mic_phase | EFFECTIVE mic decimation slot (AUTO reported as ratio-1) |
| 19 | mic_ratio | `xua_csd_get_usb_ratio()` again |
| 20 | mic_mode | 0=auto, 1=operator-set |
| 21 | decim_slot | `g_csd_dec_slot` — the slot the port decimator latches |
| 22 | decim_pub | `g_csd_dec_pub` — ADC1 words PRESENTED to the mic stream by the port decimator, incremented PER CHANNEL at both publish sites in `xua_audiohub.xc` (~2x mic frame rate/s; 95,994/s at 48 kHz armed = the 2x48k presentation witness, NOT a resampler compute counter) |
| 23-36 | reserved | F3..F16 held at 0 for the phase sweep (count sacred, append-only) |
| 37-42 | adc_cnt0/1, adc_or0/1, adc_sum0/1 | raw ADC1 port-IN witnesses (`xua_audiohub.xc`) |
| 43-45 | xfer_n, xfer_ticks, xfer_max | mic capture transfer count, total stall ticks, worst stall (10 ns); zero with a live stream means the increments are compiled out (`CSD_XFER_TIMING` gates increments, not the reply) |

`DIAG:UPSAMPLing:STATe?` = `enabled, applied(codec-OSF-grant), sf, rf, refusals`.
Reports must quote field NAMES, never bare "index N".

## Preset contract (agreed target design, owner 2026-11-10 -- recorded, NOT implemented)

PRESET 0 = upsampling bypass, EQ bypass   (today: preset 0 = engine off -- compatible)
PRESET 1 = upsampling enabled, EQ bypass  (today: preset 1 = DELAY -- CONFLICT, a
         separate follow-up owns the renumbering; do not change it here)
PRESET 2 = upsampling bypass, EQ enabled  (today: preset >=2 loads the shelf kernel --
         compatible)
PRESET 3 = upsampling enabled, EQ enabled

Upsampling and EQ are selected by LOADING DIFFERENT KERNELS into the ONE
fd_block_fir engine (the EQ kernel and the R-phase polyphase interpolation bank,
cascaded when both are on) -- not necessarily two separate clients. Once the
renumbering lands, `DIAG:UPSAMPLing:STATe` must become CONSISTENT WITH, not
independent of, the preset (today's two-independent-clients model is the
pre-renumbering state).

## Root causes fixed this round

1. **DSP subordinate to the resampler** — `csd_dsp_frame()` had a `csd_ups_active()`
   early-return ("upsampler owns the frame, shelf stands down"). Deleted.
2. **Sticky enable** — `AUDIOHW_CMD_TRIM_UPS_GET` replied `csd_trim_ups_get() | s_osf_want`,
   and `s_osf_want` was OR-in only, re-fed on every `AudioHwConfig` re-pass. Fixed with an
   operator-disable latch (`s_osf_session_off`) cleared only by an explicit enable.
3. **Codec OSF bypass granted on a bare frame-clock test** — that test is also true for a
   384 kHz host stream, so the bypass was granted without resampling and starved the
   modulators into silence at 192/384 kHz. Grant now requires the family frame clock **and**
   that the fabric force actually landed; the rate-change mirror revokes the grant when the
   client is off.

## NOT done

  block-compute witnesses did not move. The zero-order-hold stub that once passed at ratio 8
  belonged to the deleted engine and was never re-implemented on the block engine.
- **`DIAG:UPSAMPLing:INFO?` field map is unmapped** — layout went to 18 base + 37 tail; no
  name has been read from the format string since. Index 22 is unidentified.
- **Acoustic coherence across rates not re-measured since the fix.** Last matrix (build
  `.62`, pre-fix) showed silence at 192 k and 384 k (−77…−80 dBFS) and incoherent levels at
  48 k/96 k. Pre-merge baseline was −44 dBFS at every rate.
- `run_gate_armed.py --skip-arm` issues malformed readbacks (`DIAG:DSP:PRESet 1?`,
  `DIAG:UPSAMPLing:STATe 0?`) → prints false `REJECTED … [DID NOT TAKE]`. The writes do take.
- `csd_decim_probe.py` reads INFO? indices 21/22/37/38, which no longer mean what they did.
- Shelf gain question unresolved: pre-merge the "bass shelf" cost ~5 dB absolute gain where
  it should be flat outside the bass. New polyphase tables have no acoustic judgement yet.
- Right-channel wire drain: lib_xua calls `csd_ups_slot` only in the even/left loop, so
  `popsR` is expected 0 until that repo's owner lands its fix.
- 44.1 kHz family (352800 wire) never exercised on the new engine.
- 17 generated `tools/dsp/csdups_*.npy` arrays got committed; decide keep-as-provenance or
  gitignore.
- Diagnostic macros left in the tree from the investigation (`CSD_ADC_DIAG`,
  `CSD_XFER_TIMING`) need a keep-or-remove decision.
